# 从零重建 Blog-Yihe：按依赖顺序创建文件

> 本手册讲"怎么从空目录按阶段搭起来"。如果你接手的是**已经存在但编译不过**的目录，
> 先看同目录的《修复记录-从报错到可运行.md》，那里记录了每个报错的根因、新增/修改了哪些文件、
> 以及被注释掉（未删除）的旧代码位置。

本手册的目标是：从一个空文件夹重新搭建出当前博客。不要一次复制所有 144 个文件；按下面阶段完成，每一阶段都能运行和验证。

## 1. 总体建造顺序

~~~text
Next.js 最小页面
→ 全局样式、路径别名、公共导航
→ 首页卡片与配置数据
→ 只读文章系统
→ 写作编辑器与图片预览
→ GitHub App 保存
→ 项目、分享、友链、图片墙等内容管理
→ RSS、Sitemap、Live2D、工具页和特效
~~~

每个阶段结束都运行 pnpm build。若构建失败，只修复刚创建的文件，不要继续添加功能。

## 2. 阶段一：可启动的 Next.js 项目

### 2.1 新建目录和项目

在 PowerShell 中执行：

~~~powershell
mkdir Blog-Yihe-Rebuild
cd Blog-Yihe-Rebuild
git init
pnpm create next-app@latest . --ts --eslint --app --src-dir --use-pnpm --import-alias "@/*"
pnpm add next@16.0.10 react@19.2.1 react-dom@19.2.1
pnpm add zustand swr motion lucide-react sonner clsx tailwind-merge dayjs marked shiki katex html-react-parser jsrsasign ts-debounce
pnpm add -D tailwindcss@4 @tailwindcss/postcss prettier prettier-plugin-tailwindcss @types/node @types/react @types/react-dom typescript
~~~

不要在当前正在运行的博客仓库里执行以上初始化命令；它们只用于全新重建目录。

### 2.2 第一个文件批次

按顺序创建：

~~~text
src/
  app/
    layout.tsx
    page.tsx
  config/
    site-content.json
  styles/
    globals.css
  consts.ts
postcss.config.mjs
tsconfig.json
~~~

创建 src/config/site-content.json：

~~~json
{
  "meta": {
    "title": "我的博客",
    "description": "一个重新搭建的个人博客",
    "username": "Your Name"
  },
  "theme": {
    "colorBrand": "#2fcbe7",
    "colorPrimary": "#5B423F",
    "colorSecondary": "#8b7667",
    "colorBrandSecondary": "#eec25e",
    "colorBg": "#d4e8f3",
    "colorBorder": "#ffffff",
    "colorCard": "#ffffff99",
    "colorArticle": "#ffffffcc"
  }
}
~~~

创建最小 src/styles/globals.css：

~~~css
@import 'tailwindcss';

:root {
  --color-brand: #2fcbe7;
  --color-primary: #5b423f;
  --color-bg: #d4e8f3;
}

html, body {
  min-height: 100%;
  margin: 0;
  color: var(--color-primary);
  background: var(--color-bg);
}
~~~

创建 src/app/layout.tsx：

~~~tsx
import '@/styles/globals.css'
import type { Metadata } from 'next'
import siteContent from '@/config/site-content.json'

export const metadata: Metadata = {
  title: siteContent.meta.title,
  description: siteContent.meta.description
}

export default function RootLayout({ children }: Readonly<{ children: React.ReactNode }>) {
  return (
    <html lang='zh-CN'>
      <body>{children}</body>
    </html>
  )
}
~~~

创建 src/app/page.tsx：

~~~tsx
import siteContent from '@/config/site-content.json'

export default function HomePage() {
  return (
    <main className='mx-auto max-w-3xl p-10'>
      <h1 className='text-4xl font-bold'>{siteContent.meta.title}</h1>
      <p className='mt-4'>{siteContent.meta.description}</p>
    </main>
  )
}
~~~

确保 tsconfig.json 中有别名：

~~~json
{
  "compilerOptions": {
    "baseUrl": ".",
    "paths": { "@/*": ["./src/*"] }
  }
}
~~~

将 package.json 脚本设为：

~~~json
{
  "scripts": {
    "dev": "next dev -p 2025",
    "build": "next build",
    "start": "next start"
  }
}
~~~

### 2.3 检查点 A

~~~powershell
pnpm dev
pnpm build
~~~

打开 http://localhost:2025，能看到标题与描述才进入下一阶段。

## 3. 阶段二：全局外壳、样式与导航

目标：所有页面都有统一布局与导航。

### 3.1 创建顺序

~~~text
src/
  styles/theme.css
  styles/article.css
  hooks/use-size.ts
  hooks/use-center.ts
  lib/utils.ts
  layout/index.tsx
  layout/backgrounds/blurred-bubbles.tsx
  components/nav-card.tsx
  components/dialog-modal.tsx
  components/scroll-top-button.tsx
  app/blog/page.tsx
  app/about/page.tsx
  app/projects/page.tsx
  app/share/page.tsx
  app/bloggers/page.tsx
~~~

先将 src/layout/index.tsx 做成最小全局容器：

~~~tsx
'use client'

import { PropsWithChildren } from 'react'
import { Toaster } from 'sonner'
import NavCard from '@/components/nav-card'

export default function Layout({ children }: PropsWithChildren) {
  return (
    <>
      <Toaster position='bottom-right' />
      <main className='min-h-screen p-6'>{children}</main>
      <NavCard />
    </>
  )
}
~~~

在根布局中用 Layout 包住 children。

再创建最小导航 src/components/nav-card.tsx：

~~~tsx
import Link from 'next/link'

const items = [
  { label: '首页', href: '/' },
  { label: '文章', href: '/blog' },
  { label: '项目', href: '/projects' },
  { label: '关于', href: '/about' }
]

export default function NavCard() {
  return (
    <nav className='fixed top-4 left-1/2 z-50 flex -translate-x-1/2 gap-4 rounded-full bg-white/80 px-5 py-3 shadow backdrop-blur'>
      {items.map(item => <Link key={item.href} href={item.href}>{item.label}</Link>)}
    </nav>
  )
}
~~~

每个目标页先只导出一个简单标题。确认跳转可用后，再迁移当前项目的 SVG 图标、激活态与 Motion 动画。

### 3.2 检查点 B

依次访问 /、/blog、/projects、/about。没有 404、控制台没有错误，再执行 pnpm build。

## 4. 阶段三：首页卡片系统

目标：做出当前项目的可配置卡片首页，但尚不接入 GitHub 保存。

开始此阶段前，先将阶段一的 `../src/app/(home)/page.tsx` **移动**为 `src/app/(home)/page.tsx`；不要同时保留两个文件。它们都会映射到 `/`，同时存在会造成路由冲突。括号目录只是代码分组，不会出现在 URL 中。

### 4.1 先创建数据和状态

~~~text
src/
  config/card-styles.json
  config/card-styles-default.json
  components/card.tsx
  app/(home)/
    page.tsx              # 由阶段一的 app/page.tsx 移动而来
    stores/config-store.ts
    stores/layout-edit-store.ts
~~~

card-styles.json 的最小版本：

~~~json
{
  "hiCard": { "width": 360, "height": 288, "order": 1, "offsetX": null, "offsetY": null, "enabled": true },
  "navCard": { "width": 280, "height": 434, "order": 2, "offsetX": null, "offsetY": null, "enabled": true },
  "articleCard": { "width": 266, "height": 160, "order": 3, "offsetX": null, "offsetY": null, "enabled": true }
}
~~~

实现顺序必须是：

1. config-store.ts：从两个 JSON 读取初始数据，暴露 siteContent、cardStyles 和更新方法。
2. card.tsx：只负责统一尺寸、绝对坐标和 Motion 动画。
3. hi-card.tsx：中央介绍卡片。
4. art-card.tsx、aritcle-card.tsx：首图和文章入口。
5. social-buttons.tsx、clock-card.tsx、calendar-card.tsx。
6. share-card.tsx、write-buttons.tsx、like-position.tsx。
7. hat-card.tsx、beian-card.tsx：可选项最后添加。

每张卡片均从 Store 读取自己的配置；不要把宽高写死在 TSX 中。

### 4.2 加入手机端

先实现 hooks/use-size.ts，以 640px 为小屏断点。小屏下首页使用纵向 Flex 排列，桌面端才使用绝对坐标。卡片拖拽必须最后实现。

### 4.3 检查点 C

- 改 JSON 中宽高，刷新后能看到卡片尺寸变化。
- enabled 为 false 的卡片不会显示。
- 桌面与手机宽度都不发生严重重叠。
- pnpm build 成功。

## 5. 阶段四：只读博客

目标：不用私钥也能写 Markdown 文件并在网页阅读。

### 5.1 创建文章数据

~~~text
public/blogs/
  index.json
  categories.json
  hello-world/
    index.md
    config.json
src/
  app/blog/page.tsx
  app/blog/[id]/page.tsx
  app/blog/types.ts
  hooks/use-blog-index.ts
  hooks/use-categories.ts
  lib/blog-index.ts
  lib/load-blog.ts
  lib/markdown-renderer.ts
~~~

文章配置最小示例：

~~~json
{
  "title": "Hello World",
  "date": "2026-01-01T00:00:00.000Z",
  "summary": "第一篇测试文章。",
  "tags": ["开始"],
  "hidden": false,
  "category": "随笔"
}
~~~

### 5.2 文件实现顺序

1. types.ts：定义文章索引与文章配置类型。
2. load-blog.ts：根据 slug 读取 Markdown 和配置。
3. blog-index.ts 与 use-blog-index.ts：读取列表索引。
4. /blog/[id]：先输出原始正文。
5. markdown-renderer.ts：再加入 Markdown、代码高亮、数学公式。
6. /blog：最后做文章列表、分类与时间筛选。
7. 增加 components/blog-toc.tsx、blog-sidebar.tsx、code-block.tsx 和阅读状态。

### 5.3 检查点 D

/blog 可看到 Hello World，/blog/hello-world 可显示正文。这一阶段完全不应依赖 GitHub App。

## 6. 阶段五：文章编辑器与本地状态

目标：浏览器中可新建、编辑、预览文章和图片；刷新丢失草稿是正常的。

按此顺序创建：

~~~text
src/app/write/
  types.ts
  stores/write-store.ts
  stores/preview-store.ts
  components/editor.tsx
  components/preview.tsx
  components/sidebar.tsx
  components/actions.tsx
  components/sections/meta-section.tsx
  components/sections/cover-section.tsx
  components/sections/images-section.tsx
  components/ui/tag-input.tsx
  hooks/use-write-data.ts
  hooks/use-load-blog.ts
  page.tsx
  [slug]/page.tsx
src/lib/file-utils.ts
~~~

实现顺序：

1. 定义 PublishForm 与 ImageItem。
2. write-store.ts 只实现标题、slug、正文与 reset()。
3. editor.tsx 先使用普通 textarea 更新 Store。
4. preview.tsx 复用 Markdown 渲染器。
5. 添加标签、日期、摘要、封面和图片列表。
6. addFiles() 对图片算 SHA-256 去重；删除图片时调用 URL.revokeObjectURL()。
7. 最后实现 [slug]/page.tsx，加载已有文章填回编辑表单。

检查点：/write 中输入内容可以预览，pnpm build 可通过。

## 7. 阶段六：GitHub App 保存能力

目标：前台修改真正写入 GitHub 分支。这是最后才接入的能力，因为它拥有写入权限。

### 7.1 底层文件创建顺序

~~~text
src/
  consts.ts
  hooks/use-auth.ts
  lib/aes256-util.ts
  lib/github-client.ts
  lib/auth.ts
~~~

实现顺序：

1. consts.ts：读取 owner、repo、branch、App ID 环境变量。
2. aes256-util.ts：会话缓存 PEM 的加/解密工具。
3. github-client.ts：依次实现 JWT 签名、installation 查询、token 创建、blob/tree/commit/ref API。
4. auth.ts：优先读取短期 token；没有 token 时用 PEM 签 JWT，再换 Installation Token。
5. use-auth.ts：用 Zustand 管理私钥导入、清除和鉴权状态。

业务服务按如下顺序创建：

~~~text
1. app/(home)/services/push-site-content.ts
2. app/write/services/push-blog.ts
3. app/write/services/delete-blog.ts
4. app/blog/services/save-blog-edits.ts
5. app/blog/services/batch-delete-blogs.ts
6. projects/share/bloggers/pictures/about/snippets 的 push-*.ts
~~~

每项保存都统一遵循：

~~~text
getAuthToken
→ getRef
→ createBlob（每个文件）
→ createTree
→ createCommit
→ updateRef
~~~

不要在页面组件中直接调用 GitHub API；所有请求都集中在 lib/github-client.ts，业务服务只组装哪些文件要变化。

### 7.2 加入首页配置界面

最后创建：

src/app/(home)/config-dialog/

  home-layout.tsx
  color-config.tsx
  site-settings/
    index.tsx

    art-images-section.tsx
    background-images-section.tsx

测试私钥与 GitHub App 的获取方式见同目录中的 GitHub App 私钥获取与配置教程。

## 8. 阶段七：其他内容管理模块

每一个模块都遵循固定模板：数据 JSON → 类型 → 卡片 → 弹窗 → 页面 → 保存服务。

| 顺序 | 模块 | 主要文件 |
| --- | --- | --- |
| 1 | 项目 | app/projects/list.json、页面、项目卡片、创建/图片弹窗、push-projects.ts |
| 2 | 分享 | app/share/list.json、页面、网格、分享卡片、创建/Logo 弹窗、push-shares.ts |
| 3 | 友链 | app/bloggers/list.json、页面、网格、友链卡片、创建/头像弹窗、push-bloggers.ts |
| 4 | 图片墙 | app/pictures/list.json、页面、随机布局、上传弹窗、push-pictures.ts |
| 5 | 关于页 | app/about/list.json、页面、push-about.ts |
| 6 | 代码片段 | app/snippets/list.json、页面、push-snippets.ts |

每加一个模块，先验证未导入私钥时可以阅读，再验证保存只影响该模块的数据文件和图片目录。

## 10. 最终验收

最终目录的核心应为：

~~~text
src/
├─ app/          页面、内容管理、RSS、Sitemap
├─ components/   通用界面
├─ config/       站点和卡片配置
├─ hooks/        React Hook
├─ layout/       全站外壳和背景
├─ lib/          认证、GitHub、Markdown、文件工具
├─ styles/       全局、主题、文章样式
├─ svgs/         图标
└─ consts.ts     常量与环境变量
~~~

最终依次执行：

~~~powershell
pnpm build
pnpm dev
~~~

并手工确认：

- 首页的桌面端、手机端均可访问；
- /blog、/blog/hello-world、/write、/projects、/about 没有 404；
- 未导入 PEM 时只不能保存，不影响阅读；
- 在测试仓库导入 PEM 后可保存一次；
- .pem 与 .env.local 没有提交进 Git。
