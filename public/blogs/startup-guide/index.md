## 启动之前

> [!NOTE] 运行环境
> 需要 Node.js 20 或更高的版本，包管理器用 npm 或 pnpm 都可以。
> 仓库里已经带好了 `pnpm-lock.yaml`，习惯 pnpm 的话直接沿用即可。

先确认版本：

```bash
node -v
npm -v
```

如果版本过低，去 [Node.js 官网][node-docs] 下载 LTS 版本重装即可。

## 四步启动

### 第一步：安装依赖

```bash
npm install
# 或者
pnpm install
```

### 第二步：准备环境变量

复制 `.env.example` 为 `.env.local`，填上自己的 GitHub 身份：

```bash
cp .env.example .env.local
```

至少要改这几项：

| 变量 | 作用 |
| --- | --- |
| `NEXT_PUBLIC_GITHUB_OWNER` | 仓库所属的用户名 |
| `NEXT_PUBLIC_GITHUB_REPO` | 仓库名 |
| `NEXT_PUBLIC_GITHUB_BRANCH` | 默认分支，一般是 `main` |
| `NEXT_PUBLIC_GITHUB_APP_ID` | GitHub App 的 App ID |
| `NEXT_PUBLIC_GITHUB_ENCRYPT_KEY` | 加解密本地缓存私钥的口令 |

> [!WARNING] 私钥和口令不要进仓库
> `.env.local` 已经在忽略列表里；`NEXT_PUBLIC_GITHUB_ENCRYPT_KEY` 仍然会进入浏览器包，所以请把它当成“本地会话口令”，不要复用你在别处的密码。

### 第三步：启动开发服务器

```bash
npm run dev
```

项目约定端口是 `2025`，启动后打开 <http://localhost:2025> 就能看到首页。

### 第四步：完成身份认证

回到首页，点击「身份认证」，先输入认证密码，再选择你的 `.pem` 私钥文件。认证成功后：

- 首页出现「写文章」入口；
- `/blog` 列表出现编辑按钮；
- 图片墙的上传、文章的编辑与删除才会显示出来。

> [!TIP] 本地与 GitHub 双写
> 开发模式下发布成功后，`/api/dev-sync` 会顺手把远端提交拉回本地，省去手动 `git pull`。生产环境会自动跳过这一步。

## 用新版写作器写第一篇

新建文章时，标题和正文是分开的两行：

1. 顶部单独一行填标题；
2. 下面写正文，支持从 `#` 到 `######` 的六级标题；
3. 工具栏可以插入分隔线、任务列表、表格、公式块、警告框与脚注。

> [!IMPORTANT] 发布前先打星
> 随笔文案和文章的发布流程一样，都会同时写入本地与 GitHub；区别是随笔需要在发布前先把喜爱程度选好。

### 标题层级

#### 四级标题

##### 五级标题

###### 六级标题

标题编号不需要手动输入，渲染时会自动带上对应的 `#` 标记。

### 脚注与引用式链接

正文里写 `[^1]` 就能生成脚注，文末用 `[^1]: 内容` 定义；链接也可以先起一个名字，再在文末统一定义：[Next.js 文档][next-docs]。

### 警告框

```markdown
> [!NOTE]
> 这是一条普通提示。

> [!WARNING]
> 这是一条警告。
```

可用的类型有 `NOTE`、`TIP`、`IMPORTANT`、`WARNING`、`CAUTION`，渲染时会自动配色。

### 水平分割线

单独一行写三个短横线即可：

```markdown
---
```

## 常见问题

> [!CAUTION] 端口被占用
> 如果 `2025` 端口已经被别的程序占用，`npm run dev -- -p 2026` 可以临时换端口；本地同步请求跟随当前页面地址，不需要改配置。

> [!NOTE] 页面没有立刻更新
> GitHub 提交后，线上站点需要等待一次部署完成；开发环境则会通过本地同步立即生效。
